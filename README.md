# 인생 한 턴 — Life Turn Sim

한 달에 한 번, 인생을 한 칸씩. 선택이 쌓여 인생이 되는 모바일 웹 턴제 시뮬레이션 **「인생 한 턴」**입니다.
이벤트 **2,200개**로 1세부터 80세까지 960개월을 거의 매달 새 사건으로 채웁니다. 유아기의 씨앗이 초·중·고·대학·사회·가정·중년·노년까지 **플래그로 이어지는 장기 인과 체인**과, 같은 나이에도 다른 풀이 열리는 **다분기 이벤트**를 갖췄습니다.
아이폰 사파리(390×844) 기준으로 만들었고, 빌드 도구 없이 정적 파일만으로 동작합니다.

## 플레이 방식

1. 시작 나이 7개 중 하나를 고릅니다.
   `1세(출산)` · `8세(초등학교 입학)` · `14세(중학교 입학)` · `17세(고등학교 입학)` · `20세(대학교 입학)` · `25세(취직)` · `35세(결혼)`
   아래 **출발 시나리오**(한국 현실 · 90년대생 · 재벌가 막내 · 흙수저)를 고르고, 전당에 내 기록이 있으면 **가문 이어받기**로 이전 인생의 재산·재능을 물려받아 시작할 수 있습니다.
2. `[인생 시작하기]`를 누르면 **1개월 단위** 턴이 시작됩니다. 표기는 `1세 · 1개월차` ~ `1세 · 12개월차`.
3. 이벤트 카드에서 2~4개의 선택지 중 하나를 고르면 **결과 스토리 + 스탯 변화**가 즉시 표시됩니다.
4. `[다음 1개월 진행하기 →]`를 누르면 한 달이 지나고, 12개월차 다음은 `2세 · 1개월차`가 됩니다.
   결과 화면에는 **5초 카운트다운**이 함께 돌아, 손대지 않아도 다음 턴으로 넘어갑니다(아래 「5초 자동 넘김」).
5. 하단 `📖 인생 일지`에서 지나온 선택을 시간순으로 다시 볼 수 있고, `인생 요약`에서 언제든 칭호가 붙은 요약 카드를 볼 수 있습니다.
6. 80세가 지나면 엔딩(인생 요약)이 나옵니다.

## 5초 자동 넘김

선택을 마치면 결과 카드 아래에 `⏱ 5초 후 다음 턴` 칩과 `⏸ 일시정지` 토글이 뜨고, 1초 단위로 줄어들다가 5초 뒤 자동으로 다음 달로 넘어갑니다.

- **빨리 넘기기**: `[다음 1개월 진행하기 →]` 버튼은 타이머를 즉시 해제하고 바로 넘깁니다.
- **천천히 읽기**: `⏸ 일시정지`를 누르면 남은 초를 붙잡아 두고 멈춥니다. `▶ 다시 시작`을 누르면 남은 시간부터 이어집니다.
  정지 상태는 `localStorage`(`lifeTurnSim.autoPaused`)에 남아, 새로고침해도 결과를 다 읽을 때까지 자동으로 넘어가지 않습니다.
- **멈춰야 하는 화면**: 졸업 결산·80세 엔딩으로 넘어가는 턴에서는 카운트다운 대신 `🎓 다음은 졸업 결산` / `🌅 다음은 인생 마무리` 안내만 띄우고 자동으로 넘기지 않습니다.
- **타이머 정리**: `새로 시작` · `전당` · `인생 일지` · `인생 요약` · `제안·제보`를 열거나, 되돌리기·다시 뽑기·긴급 회복을 쓰거나, 탭이 백그라운드로 가면 타이머를 끕니다(돌아왔을 때 모르는 사이 넘어가 있지 않게).
- **미니 승부 중에는 없음**: 승부가 끝나 결과가 뜨는 순간부터 카운트다운이 시작됩니다.

## 🧑 성장 아바타 · 말풍선 · 단기 미션

능력치 줄 바로 아래, 사건 카드 바로 위에 붙는 한 줄 카드입니다. 매 턴 지금의 나와 상태를 한눈에 보여 줍니다.

- **아바타**: 인라인 SVG 한 장(약 2.6KB, 네트워크 요청 0). 나이대 **7단계**로 머리·옷·소품이 바뀝니다.
  유아기(1~7) 솜털 머리·배내옷 → 초등(8~13) 보울컷·교복 → 중고등(14~19) 삐죽 앞머리·후드 티 →
  대학·청년(20~25) 옆가르마·오픈 재킷 → 직장인·성인(26~49) 단정한 옷·정장 넥타이 →
  중년(50~64) 센 머리·안경·카디건 → 노년(65~80) 은발·안경·조끼.
- **표정·소품**: 체력이나 멘탈이 **35 미만**이면 다크서클·땀방울·시무룩한 입, 둘 다 높으면 활짝 웃는 얼굴.
  매력 78 이상이면 반짝이, 재산 3,000만 이상이면 선글라스, **재산 1억 이상이면 왕관**, 재산이 마이너스면 반창고가 붙습니다.
- **말풍선**: 지금 능력치 → 직전 선택의 결과 → 나이대 기본 대사 순으로 한두 줄을 고릅니다.
  `체력 좀 챙겨야겠다…` · `멘탈이 흔들린다, 심호흡 한 번` · `통장이 얇아지고 있어...` · `멘탈 최고조!`
- **단기 미션**: 나이대마다 목표 하나와 진행률(%) 막대가 있고, **그 나이대에 들어설 때의 능력치(출발선)** 에서 잽니다.

  | 나이대 | 미션 | 목표 (출발선 + 성장폭) | 달성 보너스 |
  |---|---|---|---|
  | 유아기 | 호감도 키우기 | 호감도 +19 (보통 46→65) | 호감도 +3 · 매력 +2 |
  | 초등 | 기초 쌓기 | 역량 +6 (보통 48→54) | 역량 +3 |
  | 10대 | 실력 만들기 | 역량 +8 (보통 55→63) | 역량 +3 · 멘탈 +2 |
  | 20대 | 나를 가꾸기 | 매력 +8 (20세 시작 60→68, 이월 88→89) | 매력 +3 · 호감도 +2 |
  | 30·40대 | 일에서의 역량 | 역량 +8 (보통 75→83) | 역량 +3 · 멘탈 +2 |
  | 50대 | 몸 챙기기 | 체력 +12 (보통 63→75) | 체력 +3 · 멘탈 +2 |
  | 노년 | 건강 지키기 | 체력 +9 (보통 80→89) | 체력 +3 · 멘탈 +2 |

  목표를 넘는 순간 카드가 한 번 번쩍이고 `🎯 … 미션 달성!` 토스트와 보너스가 붙습니다.
  한 인생에서 같은 나이대 미션은 **한 번만** 받습니다(`state.missions`).
- **출발선(base)은 그 나이대에 들어설 때의 값**: 진행률은 `(지금값 − base) / (목표 − base)`이고,
  `base = 출발선 − 0.35/0.65 × (목표 − 출발선)` 입니다. 그래서 **어느 나이로 시작해도, 1세부터 이어서 와도 막대가 늘 35%에서 출발**하고,
  그 구간에서 실제로 능력치를 쌓아야 100%가 됩니다(출발선은 `state.missionBase[나이대]`에 한 번만 적고, 저장본에도 남습니다).
  예전에는 목표가 절대값이라 20대 매력 60→70 은 시작부터 86%, 35세 재산 9,500만→3,000만 은 시작하자마자 달성이었습니다.
- **목표는 그 구간에서 실제로 오르는 폭**: 나이대마다 `gain`(바라는 성장폭)이 있고, 목표는 `출발선 + gain` 입니다.
  능력치에는 실제 천장(`ceil` — 88을 넘으면 최고치 유지 규칙이 눌러 내립니다)이 있어, 목표가 천장을 넘지 않게 자릅니다.
  그래서 10대·20대처럼 이미 높은 능력치는 큰 폭을, 50대·노년처럼 천장에 가까운 능력치는 작은 폭(+8~12)을 요구합니다.
  천장을 **이미 넘긴** 능력치로 나이대에 들어서면 그 목표는 이미 이룬 것으로 보고 시작부터 `달성 ✓`로 표시합니다.
  미션 정의가 재산(`asset`)을 가리키면 빚일 때 목표가 `빚 청산`으로 바뀌고 오른쪽에 지금 빚(`-4천만원`)을 보여 줍니다(지금 일곱 나이대는 모두 능력치를 씁니다).
- **왜 30·40대는 재산이 아니라 역량인가**: 성인 구간(26~49세) 사건의 재산 효과는 선택 한 번당 평균 −62만원이고, 35세에 9,500만으로 시작해도 49세엔 −2,800만~6,800만까지 줄어듭니다(무작위·탐욕·돈 우선 플레이 실측).
  재산 목표는 모아도 닿지 않아, 그 구간 사건(커리어)과 맞는 **역량**을 목표로 삼았습니다. 50대 재산 미션도 같은 이유로 50대에 이월되는 재산(무작위 플레이 중간값 −1.7억)에서 달성할 수 없어 체력으로 바꿨습니다.
- **스탯 팝업**: 선택으로 능력치나 재산이 바뀌면 해당 능력치 카드 바로 위에서 `+5` · `-15만` 배지가 떠올랐다 사라집니다.
  `position: absolute`라 능력치 줄 배치는 흔들리지 않고, 미션 보너스는 0.4초 뒤 한 칸 위에 따로 뜹니다.
- **붙박이 배치**: 아바타 카드는 사건 카드와 함께 스크롤되되 위쪽에 **sticky**로 붙어 있어, 결과를 읽으려고 스크롤해도 지금 표정과 미션 진행률이 계속 보입니다.
- **생애 진행도는 하단 도크 위**: `🍼 유아기 ─── 1 / 80세` 막대는 이벤트 카드 안(되돌리기 줄 위)이 아니라 **하단 `인생 일지 | 다음 1개월 진행하기` 줄 바로 위**에 붙박이로 있습니다(`#lifeBar`). 스크롤 영역(`#stage`) 밖의 flex 줄이라 카드가 짧든 길든 늘 같은 자리에 있고, 스폰서 배너가 떠 있으면 `배너 → 진행도 → 액션 버튼` 순서로 배너와 도크 사이에 들어갑니다. 진행도 줄과 버튼 줄은 경계선을 지워 한 덩어리 도크로 보이게 했습니다.
  짧은 화면(높이 720px 이하, 390×664 등)에서는 카드를 더 납작하게(약 58px) 줄여 사건 카드·선택지가 덜 밀리게 했습니다.

## 🏅 칭호·인연 도감 (유년·학창기)

1~19세에만 열리는 숨은 칭호 **20종**입니다. 특정 선택(플래그)과 스탯이 맞물릴 때 해금되고, 해금 순간 상단에 배지 팝업이 뜹니다(누르면 도감으로).

- 예: `🍼 조리원 우량아`(우렁찬 아기) · `🍚 급식실 1등`(대식가 + 체력 60 이상, 7~13세) · `👑 골목대장` · `📖 책벌레` · `⚽ 운동장 축구왕` · `💌 첫사랑` · `🌙 암산 천재`(숫자 씨앗 + 멘탈 65 이상)
- 칭호 16종 + 인연 4종(골목대장·동물의 친구·단짝·첫사랑). 20종 모두 실제 이벤트 플래그로 도달할 수 있습니다.
- 해금 기록은 `localStorage`(`lifeTurnSim.titles.v1`)에 **판과 무관하게 누적**됩니다. 새 인생을 시작해도 도감은 남습니다.
- **도감 여는 곳**: 시작 화면 상단 `🏅 칭호 도감`, 명예의 전당 상단 `🏅 칭호·인연 도감` 카드, 해금 배지 팝업.
- 도감은 `12 / 20 수집 · 60%` 진행 막대와, 잠긴 칭호의 해금 나이대(`7~13세에 해금`)를 보여 줍니다.

## ⚡ 5~10초 미니 승부 (전 연령 · 45개 이벤트)

유년(6~7세)부터 노년(80세)까지, 장면에 맞는 짧은 승부가 붙습니다. 한 번에 하나씩, 누르면 5~10초 안에 승/패가 갈립니다.

| 승부 | 방식 | 주로 나오는 곳 |
| --- | --- | --- |
| 🎲 주사위 | 두 개를 굴려 합을 겨룹니다. 동점이면 한 번 더 | 딱지치기·청소 당번·동호회 내기 |
| ✌️ 가위바위보 | 손을 고르면 상대가 즉시 냅니다. 비기면 다시 (3번 비기면 패) | 소개팅·반장 단일화·손주 놀이 |
| 🎯 타이밍 | 좌우로 움직이는 막대를 초록 구간에서 멈춥니다 | 면접·계주 바통·자유투·횡단보도 |
| 🪙 동전 | 앞/뒤 중 하나를 고르고 0.8초 플립 애니메이션 뒤 결과 | 유치원 문 앞·뽑기·시장 덤 |
| 🃏 하이로우 | 공개된 카드(1~13)보다 다음 카드가 높을지 낮을지 | 할머니 집·기숙사·경로당 |
| 🧮 암산 | 사칙연산 3지선다, **7초** 제한 | 받아쓰기 눈썰미·야간 계산·장보기·장기 |

- **제한 시간**: 기본 10초, 암산만 7초. 시간이 다 지나면 패배로 처리됩니다.
- 승/패에 따라 결과 문구·스탯·플래그가 갈립니다(예: 면접 승리 → `취업_성공`, 소개팅 승리 → `인연_시작`).
- 승부 중에는 자동 넘김 타이머가 없고, **결과 화면부터 5초 카운트다운**이 돕니다.
- 선택지 정의는 `choice.mini = { type, title, desc, win:{result,effects,set}, lose:{...} }`, 엔진은 `Life.choose(s, i, { miniWin })`로 승패를 받아 적용합니다.
- 검증: `python3 scripts/verify_minigames.py --serve life-sim-web` — 390×844에서 6종을 모두 열어 보고 결과·카운트다운·가로 넘침·콘솔 오류를 확인합니다.

## 💰 재테크 · 가족 카드 (직장·가정기 25~50세)

돈이 갈래를 만들고, 그 갈래가 배우자·아이에게 이어집니다.

- **청약**: 통장 가입 → 가점 정리 → 접수 → 당첨/탈락 → 계약 → 이사 날(가족과 밤새 정리 / 업체에 맡기기)
- **적금**: 자동이체 → 2년 만기 → 투자·여행·부모님 선물
- **주식**: 소액 시작 → 장이 흔들릴 때 버티기/손절/추매 → 결산(수익) 또는 부부 갈등
- **부동산**: 지인의 땅 이야기 → 서류 확인 후 투자(성공) / 한 방에 베팅(실패)
- **가족 연계**: 부부 통장, 아이 이름의 통장, 학원비 고지서, 집 넓히기, 보험 설계, 부업, 은퇴 자금 계산 — `requireFlags: 배우자 / 자녀`로 이어집니다.

## 🪃 과거의 부메랑 (중·노년기 50~80세)

1~30대에 남긴 선택을 회수하는 이벤트 14개입니다. 카드에 `🪃 과거의 부메랑` 배지와 함께 **그 플래그를 남긴 가장 이른 선택**을 짚어 줍니다.

- 예: 9세에 축구부에 들어간 선택 → 65세 `우리 손자는 왼발잡이`(동네 감독의 코치 제안)
- 예: 어릴 적 그림 씨앗 → 65세 `서랍 속 그림`(동네 전시·손주에게 물려주기), 단짝 → 50세 `오래된 친구의 제안`(동업)
- 연출: `🪃 9세 4개월차의 선택이 돌아왔습니다` + `‘축구부에 들어간다’` + 그 이벤트의 한 줄 설명(`boomerangNote`).
- 엔진: `boomerang: true` + `callback: ['플래그', ...]`, 출처 조회는 `Life.boomerangOf(state, event)`.

## 졸업 결산 · 명예의 전당

각 학교의 마지막 달(12개월차) 턴을 마치고 다음 나이로 넘어가는 순간, **졸업 결산**이 열립니다.

| 나이 | 졸업식 |
| --- | --- |
| 7세 12개월차 | 🐥 유치원 졸업식 |
| 13세 12개월차 | 🎒 초등학교 졸업식 |
| 16세 12개월차 | 📐 중학교 졸업식 |
| 19세 12개월차 | 🎓 고등학교 졸업식 |
| 24세 12개월차 | 🏛️ 대학교 졸업식 |

졸업 결산 화면은 ① 학령기 요약(선택 수·기억 2건·특성) ② **그 시절의 나에게** 회고 편지 ③ **또래와 비교**
④ **여기서 졸업하고 명예의 전당에 등록하기** / **계속 살기(80세까지 도전)** 두 갈래로 이루어집니다.

- **능력치 비교**: 체력·멘탈·매력·호감도·역량·행운·재산과 종합 점수(7개 + 종합)를, 같은 시점에 졸업한 표본의 평균과 비교해
  차이(`+8`, `-3`)·백분위(`상위 14%`)·평균선이 있는 막대그래프로 보여줍니다.
  기준 분포는 `tools/refdist.js`가 1세 시작 120판 + 각 단계 입학 나이 140판씩을 무작위 선택으로 돌려 만든
  백분위표(`assets/refdist.js`)입니다(`node tools/refdist.js 120 140`).
- **명예의 전당**: 졸업 엔딩(5단계)과 80세 완주 기록이 `localStorage`(`lifeTurnSim.hall.v1`)에 쌓입니다.
  시작 화면 우상단 `🏆 명예의 전당`과 플레이 중 상단 `🏆 전당`에서 언제든 열 수 있고,
  단계별 탭 + 점수순 정렬, 내 기록 강조(금색 테두리)와 상단 고정 카드(내 최고 기록)가 있습니다.
  첫 진입에도 비교할 수 있도록 시뮬레이션에서 뽑은 가상 인물 기록 28건을 기본 시드로 넣었습니다(`assets/hall-seeds.js`).
  전당 위에는 `내 전당 | 🏆 전체 랭킹` 두 탭이 있습니다(아래 「전체 유저 익명 랭킹」).
- **회고 편지**: 실제 스탯 구간·플래그·`history`의 마일스톤을 조합해 8~10줄의 문장을 매 판 새로 만듭니다
  (`Life.recall(s, 'grad' | 'life')`). 80세 엔딩에서는 평생을 돌아보는 회고로 나옵니다.

## 🏆 전체 유저 익명 랭킹 (2026-11-21)

명예의 전당 위에 `내 전당 | 🏆 전체 랭킹` 두 탭이 생겼습니다. **내 전당**은 지금까지처럼 이 브라우저의 기록이고,
**전체 랭킹**은 Google 로그인한 플레이어들이 등록한 인생을 모두 모아 보여 줍니다(로그인하지 않아도 볼 수 있습니다).

- **목록**: `총점 순` / `자산 순` 토글, 1~3위 메달, 캐릭터 이름·대수·나이·엔딩 칭호·등급·점수(또는 자산) 표시.
  내 기록은 테두리와 `내 기록` 배지로 강조되고, 위쪽 카드에 `내 최고 71.4 · 상위 12% · 2위 / 전체 27명`처럼 나옵니다.
  로그인 전에는 내 최고 점수(`p_my_best_score`)를 넘겨서 **서버가 계산한 백분위**를 받고,
  서버가 없으면 이 기기 전당 기록으로 백분위를 대신 셉니다.
- **등록**: 엔딩(졸업 등록·80세 완주)에서 **로그인 상태 + `새 기록 자동 등록`(기본 켜짐)**이면 자동으로 올라갑니다.
  - 로그인 전에 만든 기록은 `내 최고 기록 올리기`로 직접 올립니다(안 올린 기록이 있을 때만 보임).
  - `랭킹 이름`은 화면에서 직접 정합니다(기본 `익명 플레이어`, 최대 12자) — **이메일은 보내지도 보여 주지도 않습니다**.
  - `전체 랭킹에서 내 기록 지우기`로 서버에 올린 내 기록을 모두 지울 수 있습니다.
- **공개되는 것**: 캐릭터 이름 · 엔딩 칭호 · 인생 유형 · 점수 · 재산 · 나이 · 대수 · 출발 시나리오 · 닉네임뿐.
  `user_id`·이메일은 RPC 응답에 포함되지 않습니다(내 기록 여부는 서버가 `auth.uid()`로 판단해 `mine` 불리언만 돌려줍니다).
- **서버**: `supabase/life_sim_leaderboard.sql`(다시 실행해도 안전) — `life_sim_*` 객체만 만집니다.
  - `public.life_sim_leaderboard`: `(user_id, run_key)` 유니크 — 같은 인생은 새 행이 아니라 갱신, 한 사람 30건까지.
  - RLS를 켜고 **정책을 두지 않습니다** = 앱이 테이블을 직접 읽고 쓰지 못합니다. 모든 접근은 `SECURITY DEFINER` RPC로만.
  - `life_sim_leaderboard_list(p_sort, p_limit, p_my_best_score)` — anon 포함 공개 읽기 + 내 순위·상위 %.
  - `life_sim_leaderboard_submit(...)` — 로그인 본인만. 값 범위 검사 + **점수↔재산 정합성**(앱 공식
    `0.55 × 게이지 평균 + 재산 몫(최대 45)`에서 나올 수 없는 조합은 거부) + 분당 10건·시간당 40건 속도 제한
    + 이름·칭호에서 이메일 모양 문자열 제거.
  - `life_sim_leaderboard_remove(p_id)` / `life_sim_leaderboard_clear()` — 본인 행만.
- **SQL을 아직 실행하지 않았을 때**: 목록 자리에 `전체 랭킹 서버가 아직 준비 중입니다` 안내가 나오고,
  '내 기록'은 기기 전당 기록 기준 백분위로 보여 줍니다. 게임 진행과 전당은 그대로 동작합니다.
- **화면**: `assets/leaderboard.js`(서버 통신·닉네임·자동 등록 설정) + `index.html`의 `#hallGlobalView` + `assets/styles.css`의 `.lg-*`.

## 🧬 이전 회차 인물 — 공유 세계관 (카메오)
명예의 전당에 남긴 **내가 살았던 인생의 인물**이 다음 인생의 세계에 나타납니다.
1회차를 `상훈`으로 살고, 2회차를 `희연`으로 시작하면 — `희연`의 학교·동네·직장에 **`상훈`**이 있습니다.

- **누가 오는가**: 전당에 등록된 **내 기록**(`r.mine`)만. 가상 인물 시드 기록은 오지 않습니다.
  - **이름이 지금 플레이어와 같으면 제외** — 나를 만나지 않습니다.
  - 최근 기록부터 **최대 3명**, 같은 이름은 최신 기록 한 건만.
  - 각 인물은 전당 기록에서 이름·성별·엔딩 칭호·졸업/완주 지점·종합 점수·최고 능력치·재산 등급을 가져옵니다(성별이 없던 옛 기록은 이름 끝자리로 짐작: 상훈→남, 희연→여).
- **어떻게 나타나는가**: 카드에 `🧬 이전 회차 인물` 배지와 함께 그 사람의 지난 인생이 안내줄로 붙습니다.
  `🧬 이전 인생의 기록 — 상훈 / 80세 완주 · 종합 71점 · 호감도 84 · 억대 재산`
- **관계 진행** (`state.cameos[i].rel`): `none` → `friend`(친구) → `close`(단짝) / `dating`(연인) → `married`(부부), 또는 `parted`(스쳐 간 인연).

  | 나이 | 장면 | 조건 |
  |---|---|---|
  | 9~10 · 14~15 · 17~18 · 20~21 · 25~26 · 36~37 | 처음 만나는 자리(옆자리·모둠·급식 줄·오리엔테이션·옆 부서·윗집) | `rel = none` |
  | 27~32 | 소개팅 자리 | `rel = none` (한 번도 못 만났을 때의 두 번째 길) |
  | 27~31 | 몇 년 만의 연락(동창 모임) | `rel = friend/close` · 이성일 때 |
  | 29~34 | 오랜 친구의 제안(단짝 갈래) | `rel = friend` · 같은 성별이거나 이성 갈래가 없을 때 |
  | 32~34 | 미래를 이야기하는 밤 → 청혼 | `rel = dating` |
  | 31~34 | 어긋나기 시작한 시간 → 이별 | `rel = dating` |
  | 41~47 | 같이 사는 하루 | `rel = married` |
  | 50~58 · 66~76 | 오랜 친구의 저녁 · 창밖을 같이 보는 사람 | `rel` 에 따라 문구가 바뀜 |

- **되는지는 능력치가 가릅니다**: 선택지는 `먼저 말을 걸어본다` · `따로 만나 보자고 한다` · `진심으로 미래를 이야기한다` 같은 **하려는 일**이고,
  실제 수락·연애·결혼은 `LifeChance` 로 **호감도·매력·멘탈·행운**을 따져 정해집니다(실패하면 친구로 남거나 각자의 길로).
- **부부가 되면** `결혼`·`배우자` 플래그가 서서 기존 가정 루트(집·아이·부부 이벤트)가 함께 열립니다.
- **이미 다른 사람과 결혼한 인생**에서는 카메오 연애 갈래(소개팅·재회·청혼·이별)가 열리지 않습니다 — 결혼은 한 번입니다. 그때는 단짝·오랜 친구 갈래로 남습니다.

## ☁️ 구글 로그인 · 클라우드 동기화 (선택)

**로그인 없이 그대로 노는 게 기본**입니다. 구글 로그인은 기기를 바꿔도 이어서 하고 싶을 때만 쓰는 선택 기능이고, 로그인하지 않으면 네트워크 요청이 **0건**입니다.

- **진입**: 시작 화면 `인생 시작하기` 아래 `G Google로 로그인` 칩(안내줄 `로그인하면 기기 간에 이어집니다 (선택)`) · 명예의 전당 제목 아래 같은 줄. 로그인하면 `☁️ 동기화됨 · 이름` + `로그아웃`으로 바뀝니다. (`SHOW_APPLE_SIGNIN` 을 켜면 `Apple로 로그인` 칩이 옆에 함께 뜹니다.)
- **회원탈퇴**: 로그인 상태의 명예의 전당에 `계정 및 클라우드 기록 삭제` — 위 「🍎 App Store 출시 준비」 참고.
- **무엇이 이어지나**: 진행 중 인생(`lifeTurnSim.save.v1`) · 명예의 전당(`lifeTurnSim.hall.v1`, 🧬 카메오 인물의 근거) · 칭호 도감(`lifeTurnSim.titles.v1`). 화면 설정(자동 넘김·배너 접기)과 제보 게시판의 기기별 제한은 기기에 남깁니다.
- **합치기(merge) 규칙** — 잃지 않는 쪽으로
  - 전당: `id` 기준 합집합(같은 기록은 한 번), 내 기록은 최근 240건까지
  - 칭호: `id` 기준 합집합, 같은 칭호는 **먼저 딴 기록**을 남김
  - 진행 중 인생: 마지막으로 저장한 쪽(`updatedAt`). 단 **지금 이 화면에서 플레이 중이면 이 기기의 인생**이 이깁니다(플레이 도중 남의 기록으로 갈아치우지 않게).
  - 다른 기기에서 `새로 시작`을 누르면 그 사실(`saveAt`)도 올라가 저장본이 되살아나지 않습니다.
- **로그인 방식**: Supabase GoTrue OAuth(**PKCE S256**) — 외부 스크립트 없이 `fetch`로만. `code_verifier`는 `localStorage`(`lifeTurnSim.auth.pkce.v1`)에 두고 돌아온 `?code=`를 토큰으로 바꿉니다. 토큰 만료 60초 전에 자동 갱신하고, 401이면 한 번 갱신해 재시도합니다.
  - **갱신은 한 번만**(`refreshInflight`) — 시작 화면·전당·화면 복귀가 같은 순간에 만료된 토큰을 갱신하려 해도 리프레시 요청은 하나입니다. GoTrue 는 리프레시 토큰을 회전시키므로 두 번째 요청이 400(`Already Used`)으로 거절당하기 때문입니다. 그 사이 다른 탭이 새 세션을 저장했다면 그 토큰으로 이어 갑니다.
  - **만료 정리**: GoTrue 는 무효한 리프레시 토큰에 401 이 아니라 **400**(`validation_failed`)으로 답합니다. 400/401 로 거절되면 이 기기의 로그인 세션만 지우고(`expireSession`) 칩을 `G Google로 로그인` + `로그인이 만료됐어요 · 다시 로그인해 주세요`로 되돌립니다. 게임 기록(진행·전당·칭호)은 지우지 않으며, 이후 다시 시도해도 죽은 토큰으로 요청하지 않습니다.
  - 앱이 백그라운드로 내려가는 순간(`visibilitychange` hidden)에는 토큰 갱신을 **시작하지 않습니다** — iOS 가 페이지를 재우면 회전된 토큰을 받지 못해 세션이 죽습니다.
- **저장**: Supabase `public.life_sim_user_state`(사람 1명당 1행, 사용자당 2MB 제한) — 스키마·RLS·RPC는 `supabase/life_sim_cloud_sync.sql`(다시 실행해도 안전).
  - RLS: `auth.uid() = user_id` 인 본인 행만 `select`/`insert`/`update`/`delete`, **anon 은 권한 없음**
  - 저장은 `life_sim_put_state(p_data jsonb, p_revised_at bigint)` **security definer** RPC 하나로. 들어온 `revised_at` 이 저장된 것보다 과거면 덮어쓰지 않고 지금 상태를 돌려주고, 앱은 돌려받은 값이 다르면 한 번 더 합쳐 올립니다(여러 기기가 동시에 저장해도 최신이 남게).
  - Supabase Auth 의 Google 제공자와 리다이렉트 주소(`https://life-turn-sim.vercel.app/**`)는 대시보드에서 설정되어 있습니다(릴스핀과 같은 프로젝트 공용).
    로컬(`python3 -m http.server`)에서 진짜 구글 로그인까지 보려면 Authentication → URL Configuration 의 Redirect URLs 에 `http://localhost:포트/**` 를 한 줄 추가해야 합니다.
- **실패해도 로컬은 그대로**: 네트워크가 끊기면 칩이 `동기화 실패 · 다시 시도`로 바뀌고 저장본은 건드리지 않습니다. 아이폰에서는 `title` 툴팁이 보이지 않으므로 **칩 아래에 실제 사유를 42자로 줄여 글자로** 남깁니다(`.sync-why`). 탭을 숨기거나 다시 열 때도 한 번 맞춥니다.
- **저장은 한 번에**: 서버는 `jsonb` 라 키 순서를 바꿔 돌려주므로, 돌려받은 값이 같은지 볼 때 키를 정렬해 비교합니다(순서만 달라 두 번 올리던 것을 막음).
- **전체 랭킹은 따로**: 동기화되는 전당 전체가 아니라, 랭킹에 올린 기록만 별도 테이블(`public.life_sim_leaderboard`)에 공개됩니다
  (스키마·RPC: `supabase/life_sim_leaderboard.sql`). 무엇이 공개되는지는 위 「전체 유저 익명 랭킹」과 개인정보처리방침 1·5항에 적었습니다.

### 역량·행운 규칙 (2026-11-18 추가)

- **역량**은 나이가 들수록 높은 값에서 출발합니다(1세 44 → 35세 시작 64). 공부·시험·코딩·프로젝트·자격증·승진처럼 배우고 풀어내는 선택에서 오르고, 그 선택은 대개 체력이나 멘탈을 조금 내줍니다.
- **행운**은 출발점이 어디든 50 근처입니다. 복권·뽑기·추첨·청약·투자·소개팅처럼 결과를 맡기는 선택에서 오르내리고, **생일마다 ±3 정도 흔들리며 50 쪽으로 조금씩 당겨집니다**(`applyLuckDrift`) — 그래서 사람마다 운의 폭이 다릅니다.
- **미니 승부에 반영**: `Life.luckBias(stats)`가 행운 50을 기준으로 승률을 **-25%p ~ +25%p** 밀어 줍니다(행운 100 → 75%, 0 → 25%). 동전·가위바위보·주사위·카드 하이로우가 이 값을 쓰고, 미니 승부 화면 하단에 `🍀 행운 62 이 승률에 반영됩니다`로 표시합니다.
- **기존 이벤트에도 연결**: `assets/events/zz-ability.js`가 로드 마지막에 주제(공부·시험·코딩·자격증 / 복권·뽑기·청약·투자·소개팅)에 맞는 기존 선택지 하나에 역량 또는 행운 +1~+2를 얹습니다. 이벤트 2,200개 가운데 역량 202개·행운 45개 선택지가 두 능력치를 움직입니다(그중 자동 연결이 역량 155·행운 8).
- **엔딩**: 역량 90 이상이면 `🧠 머리로 길을 만든 사람`, 행운 90 이상이면 `🍀 행운을 끝까지 들고 간 사람`, 행운 22 이하면 `🌧️ 운이 비켜 갈 때 버틴 사람` 갈래가 붙고, 회고 편지에 머리와 운을 다루는 한 줄이 들어갑니다.
- **저장 호환**: 저장본 버전 v5. 역량·행운이 없던 v1~v3 저장본은 `migrate()`가 50으로 채워 그대로 이어지고, 카메오(`cameos`)가 없던 v4 저장본은 불러올 때 전당 기록에서 채워집니다(`stats`·`undo.stats`·`grad.stats` 모두).
- 검증: `node test/stats.js` (41항목) — 정의·프리셋·클램프·최고치 유지·저장 호환·결산 행·전당 기록·입시 합격선·행운 보정·전 연령대 이벤트.

### 밸런스 규칙 (2026-11-18 조정 · 11-21 신생아 조정)

- 시작 스탯은 **50~60대**. 한 선택지의 변화는 **±1~±3**(극적인 대형 이벤트만 ±4~±5)입니다.
- **1세(출산)만은 신생아 답게**: 시작 체력 **38** · 호감도 **46**입니다(다른 나이 시작은 그대로). 아기는 몸이 약해 유아기 선택으로 체력을 쌓아 가고, 38이라 긴급 회복 조건(체력·멘탈 30 이하)에 시작부터 걸리지도 않습니다. 출발 시나리오를 얹으면 재벌가 34 · 흙수저 42 범위입니다.
- **매달 스탯이 저절로 줄지 않습니다.** 예전의 `생활 소모(applyDrift)`는 제거했습니다 — 아무 선택도 하지 않았는데 달이 바뀌며 스탯이 빠지는 게 억울하다는 제보가 있었습니다.
- 대신 두 가지로 100에 붙지 않게 합니다.
  - **고수준 체감**: 80 이상이면 같은 +3도 0.8배, 88 이상 0.5배, 95 이상 0.25배로 오릅니다.
  - **최고치 유지**: 88을 넘긴 스탯만 달마다 아주 조금씩 88 쪽으로 내려갑니다(한 달 최대 1.4). 보통 범위(88 미만)는 그대로입니다.
- **생일 노화**: 45세부터 해가 바뀌는 달에 체력(62세부터 매력, 72세부터 멘탈)이 1씩 줄어듭니다.
- 그래서 **100을 찍기는 거의 불가능하고, 88~96 사이에서 선택으로 오르내립니다.**
- 스탯 분포가 바뀌었으므로 졸업 결산의 또래 비교 기준(`assets/refdist.js`)과 전당 시드(`assets/hall-seeds.js`)를 `node tools/refdist.js 120 140`로 다시 뽑았습니다.
- 검증: `node test/sim.js`의 `스탯 밸런스` 절 — 세대별 평균/최고, 100 도달 비율, 3턴 만의 100 도달 여부.

### 진로 갈래 · 결과 선택지 규칙 (2026-11-18)

- **진로 갈래는 하나만**: `진로_예술·체육·공학·의학·인문·교육·미디어·창업` 중 하나만 서고, 새 갈래를 고르면 나머지는 `false`가 됩니다(`LifeTracks.exclusive`). 체육 특기생이 어느새 예술 특기생이 되던 문제를 막습니다.
- 갈래를 정하는 이벤트(`tn_m20`·`tn_m32` 등)는 `when: LifeTracks.noTrack`으로 한 번만 뜨고, 예고·체육고 진학생은 별도 입학 이벤트(`tn_h90`·`tn_h91`)를 받습니다 — 특목고·자사고 입학 선택지(`high_enter`)는 숨김.
- **결과를 고르는 선택지는 두지 않습니다**: 시험·입시·면허 결과는 스탯과 그동안의 습관 플래그로 정해지고(예: `tn_h50` 합격 발표 — 멘탈·체력·성실함·성적 상승 등), 선택지는 ‘어떻게 받아들이는가’만 가릅니다. `set`·`effects`·`result`에 함수를 쓸 수 있습니다.

## 이벤트 추가하기

생애주기 모듈(`assets/events/*.js`)에 `X(...)` 한 줄로 추가하면 엔진이 자동으로 집어 갑니다.

```js
// X(stage, id, 나이(또는 [최소,최대]), 장소, 제목, 상황, 선택지[, 옵션])
X('work', 'my_event', [28, 30], '회의실', '제목', '상황 설명', [
  ['선택지 A', '결과 스토리', { mental: 2, asset: -1 }],          // 효과
  ['선택지 B', '결과 스토리', { social: 2 }, { 야근러: true }]     // 효과 + 플래그
]);

// 마일스톤(특정 나이·개월차 고정) 예
X('work', 'my_milestone', 28, '은행', '청약통장', '설명', [
  ['가입한다', '결과', { asset: -1 }],
  ['미룬다', '결과', { mental: 1 }]
], { at: [28, 4], milestone: true });

// 조건 분기 예 — 앞선 선택(플래그)이 있어야만 열리고, 스탯에 따라 확률이 달라진다
X('work', 'my_branch', [27, 34], '작업실', '작업실 임대', '설명', [
  ['얻는다', '결과', { mental: 3, asset: -300 }, { 작품활동: true }],
  ['집에서 계속한다', '결과', { mental: 1 }]
], { requireFlags: '예술가_길', minStat: { mental: 45 }, weight: function (s) { return s.flags.전시회 ? 4 : 2; } });

// 인생의 갈림길 — 같은 달의 다른 마일스톤보다 먼저 제시된다
X('college', 'my_fork', 20, '운동장', '동아리 선택', '설명', [
  ['가입한다', '결과', { hp: 3 }, { 축구부: true }],
  ['관중으로 남는다', '결과', { social: 2 }]
], { at: [20, 4], milestone: true, fork: true });
```

- `stage`: `infancy | elementary | middle | high | college | work | family | midlife | senior | any`
- **나이는 반드시 적습니다.** 그 나이 밖에서는 후보에서 아예 빠지므로 고증 오류가 나지 않습니다.
- 선택지는 2~4개, 효과는 `±1~±3`(재산은 만원 단위), `queue`로 다음 턴 후속 이벤트를 예약할 수 있습니다.
- `requireFlags`/`excludeFlags`/`minStat`/`maxStat`/`weight`/`fork`로 갈래를 만들고, `node test/branches.js`로 조건 위반 0건과 루트 도달을 확인하세요.
- 추가 후 `node tools/coverage.js`로 나이별 후보 수(13개 이상)와 `node tools/fallback.js`로 폴백 0회를 확인하세요.
